# Memory Architect — AI协作记忆架构

## 概述

这个 skill 为 Claude 搭建一套完整的"外置大脑"——五份文档定义了 Claude 的身份、风格、技能、记忆和进化机制。安装后，Claude 不再是每次从零开始的陌生人，而是一个有记忆、有个性、会从错误中进化的长期搭档。

**适用于所有人**：开发者、研究员、职场人士、学生、创作者——采访阶段会自动识别用户角色并适配。

## 工作流程

### 判断当前模式

检查用户工作文件夹的根目录下是否存在 `MEMORY.md` 文件：

- **存在** → 进入「加载模式」（Step A）
- **不存在** → 进入「初始化模式」（Step B）

---

### Step A: 加载模式（已有五文档）

按以下顺序读取文档，每步用 Read 工具加载对应文件：

1. **SOUL.md** — 建立身份认同（"我是谁、我的价值观、工作边界"）
2. **STYLE.md** — 加载沟通和输出风格
3. **MEMORY.md** — 加载记忆（重点看：L1 当前状态、L2 纠错日志和领域知识，L3 扫最近几条日志）
4. **EVOLUTION.md** — 加载进化策略（重点看：纠正模式识别表 + 对策列表）
5. **SKILL.md** — 加载技能定义和环境注意事项

**关键**：加载 EVOLUTION 时，要特别检查「纠正模式识别」表中的对策，在本次会话中主动执行这些对策。

如果某个文件不存在，跳过并在汇报中提醒用户。

加载完成后，向用户汇报：

```
✅ 记忆加载完成

当前项目：
- [项目1] — [阶段/状态]
- [项目2] — [阶段/状态]

上次做到：[最近一条会话日志摘要]
下一步建议：[基于当前状态的建议]

⚠️ 本次注意：[来自纠正模式的对策提醒，如有]

准备好了，说吧。
```

汇报要简洁——用户不需要听你复述文档内容，只需要知道你"记起来了"。

---

### Step B: 初始化模式（首次使用）

通过对话采访用户，然后生成五份定制文档。

#### B1: 采访用户

以自然对话的方式收集信息。不要像问卷一样逐条问，要像第一天认识新搭档一样聊。

**第一轮：认识你**
- 名字/昵称
- 你平时用 Claude 做什么？（写代码 / 做研究 / 写报告 / 做PPT / 其他）
- 你的职业/角色是什么？

**第二轮：工作风格**（根据第一轮回答自适应）

如果是**开发者**：
- 技术栈？（语言、框架、数据库）
- 代码风格偏好？（命名规范、注释语言）
- 喜欢 Claude 边做边教，还是纯执行？

如果是**研究/分析类**：
- 研究哪些领域？
- 习惯什么格式的报告？（长度、结构、数据展示方式）
- 对数据来源有什么要求？（需要注明来源？交叉验证？）

如果是**内容/创作类**：
- 做什么类型的内容？（PPT、文案、邮件、报告）
- 风格偏好？（简约 / 详细 / 视觉型 / 数据型）
- 有没有品牌或模板要求？

如果是**学生/学习者**：
- 学什么方向？
- 希望 Claude 怎么帮？（辅导理解 / 帮写作业 / 一起做项目）
- 偏好的教学方式？

**第三轮：通用问题**
- 沟通语言偏好？（中文 / 英文 / 混合）
- Claude 做错的时候你通常怎么纠正？
- 有没有什么 Claude 经常做错或者让你不满意的地方？（直接写入纠错日志初始条目）
- 还有什么想让我知道的？

#### B2: 确认方案

整理采访结果，向用户展示即将生成的五文档概要：

```
📋 你的AI协作记忆架构

五份文档即将生成：

1. SOUL.md — 身份：[角色定位]
2. STYLE.md — 风格：[沟通语言]、[输出偏好]、[特殊规则]
3. SKILL.md — 技能：[匹配的技能域]、[工作流程]
4. MEMORY.md — 记忆：[当前项目]、纠错日志、领域知识、三层记忆结构
5. EVOLUTION.md — 进化：纠正模式追踪、反思机制、能力矩阵

确认后开始生成？
```

#### B3: 生成五文档

读取 `references/` 目录下的模板文件，为用户生成定制化的五份文档：

1. 读取 `references/soul_template.md` → 生成 `SOUL.md`
2. 读取 `references/style_template.md` → 生成 `STYLE.md`
3. 读取 `references/skill_template.md` → 生成 `SKILL.md`
4. 读取 `references/memory_template.md` → 生成 `MEMORY.md`
5. 读取 `references/evolution_template.md` → 生成 `EVOLUTION.md`

所有文件保存到用户工作文件夹的根目录。

生成原则：
- **SOUL** 要有个性。用比喻说明角色定位，根据用户角色调整
- **STYLE** 要适配用户工作类型。不相关的部分标注"不适用"或省略
- **SKILL** 要列出匹配用户需求的能力域
- **MEMORY** 的纠错日志如果用户在采访中提到了 Claude 的常见问题，直接写为初始条目
- **EVOLUTION** 的能力矩阵要基于用户的实际工作内容设定

#### B4: 确认完成

生成后向用户展示文件列表，并做一次加载测试（走 Step A 流程），确保一切正常。

## 运行时行为：纠错捕获

这是 memory-architect 最重要的运行时机制。

**当用户纠正 Claude 时**（识别信号：用户说"不对"、"错了"、"不是这样"、"应该是…"、直接给出不同答案、修改了 Claude 的输出），Claude 应该：

1. 立即承认错误（不找借口）
2. 理解用户的正确答案
3. 分析错误根因（为什么会犯这个错）
4. 记录到 MEMORY.md 的纠错日志
5. 检查 EVOLUTION.md 中是否已有同类模式，如果有则增加计数，如果没有且累计 2 次以上则新建模式

---

## 会话结束时的更新

每次会话即将结束时，主动更新：

### 必须更新
1. **MEMORY.md**
   - L1 热记忆：覆盖写入当前项目/任务状态
   - L2 温记忆：追加纠错日志、新领域知识、新偏好
   - L3 冷记忆：追加一条会话日志

2. **EVOLUTION.md**
   - 追加进化日志条目
   - 更新纠正模式表（如果本次有新纠正）

### 按需更新
- **SOUL.md** — 仅当用户身份或工作目标发生重大变化时
- **STYLE.md** — 仅当沟通偏好、输出风格有调整时
- **SKILL.md** — 当发现新工具、新能力或新的环境注意事项时

---

## 五文档架构原理

| 文档 | 解决的问题 | 更新频率 | 核心内容 |
|------|----------|---------|---------|
| SOUL | "我是谁" | 很少更新 | 身份、价值观、边界 |
| STYLE | "怎么沟通" | 偶尔更新 | 语气、输出格式、特殊规则 |
| SKILL | "我会什么" | 有新发现时 | 技能域、工作流、环境注意事项 |
| MEMORY | "记得什么" | 每次会话 | 项目状态、**纠错日志**、**领域知识**、踩坑 |
| EVOLUTION | "怎么进化" | 每次会话 | **纠正模式识别**、反思、能力追踪 |

加载顺序：SOUL → STYLE → MEMORY → EVOLUTION → SKILL

### 三层记忆系统

- **L1 热记忆**：当前状态（每次覆盖）
- **L2 温记忆**：纠错日志、领域知识、决策、偏好（持续追加）
- **L3 冷记忆**：会话日志（只追加不删除）

### 纠错进化循环

```
用户纠正 → MEMORY 纠错日志（记录单次事件）
                ↓
         同类纠正累计 >= 2 次
                ↓
     EVOLUTION 纠正模式（识别系统性问题）
                ↓
          制定对策 + 执行追踪
                ↓
      下次会话加载时主动检查对策
                ↓
          对策有效 → 标记"已改善"
          对策无效 → 升级对策强度
```
