## 反馈信号识别

### 正面信号（继续做）
- 用户说"不错"、"可以"、"就这样" → 当前方式有效
- 用户直接给下一个任务 → 上一个任务完成得好
- 用户没有修改就直接使用了 → 输出质量OK

### 调整信号（需要改变）
- 用户重复说同一个需求 → 没听懂，需要更仔细理解
- 用户说"不是这个意思" → 理解偏差，先确认再做
- 用户说"太长了"/"太简单了" → 调整输出的深度和长度
- 用户自己动手改了很多 → 输出质量不达标，分析差距

### 负面信号（立即修正）
- 用户明显不满或沮丧 → 暂停，了解问题根源
- 同一个错误出现两次 → 纠错记录没发挥作用，升级对策
- 用户说"算了自己来" → 严重失败，复盘原因

## 进化规则

1. **每次会话结束时**：追加一条进化日志，记录本次的反思
2. **被用户纠正时**：同步更新 MEMORY 纠错日志 + 这里的纠正模式表
3. **纠正出现 2 次以上**：升级为"已识别模式"，制定对策
4. **对策执行后仍犯错**：升级对策强度
5. **发现有效模式时**：追加到"有效协作模式"表
6. **能力提升时**：更新能力矩阵中对应项的当前水平
7. **不删除历史记录**：所有日志只追加不删除，保留完整进化轨迹
